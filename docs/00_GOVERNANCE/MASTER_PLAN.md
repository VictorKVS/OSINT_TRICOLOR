# OSINT_TRICOLOR — Мастер-план инженерного проекта
Версия: 0.1 | 2026-10-15 | Статус: проектная документация, не согласована заказчиком.

## Принцип FATHER
СНАЧАЛА ДOКУМЕНТЫ → альтернативы → оценка и расчёты → проектирование комплекса → код → испытания → внедрение → развитие. Ранее сделанный MVP — только лабораторный макет, не утверждённое решение.

## Контрольные этапы
| Gate | Этап | Обязательные результаты | Условие выхода |
|---|---|---|---|
| G0 | Инициирование | паспорт, владельцы, цели, ограничения, ответственность | признана бизнес-задача |
| G1 | Обследование | заинтересованные стороны, источники, права, AS-IS | верифицирован исходный процесс |
| G2 | Бизнес-анализ | TO-BE, BPMN, регламенты, KPI, каталог кейсов | эксперт подтвердил процесс |
| G3 | Требования | BRD, SRS/ТЗ, NFR, RTM | критерии приёмки и границы согласованы |
| G4 | Комплаенс и риски | правовые основания, DPIA/152-ФЗ при применимости, threat model, evidence policy | правовой и ИБ review |
| G5 | Концепции | 3 архитектурные альтернативы, ADR, оценка build/buy/reuse | выбран обоснованный вариант |
| G6 | Экономика | sizing, нагрузка, CAPEX/OPEX, TCO, сценарии, ROI | бюджетный допуск |
| G7 | Проект | C4, ERD, API, интеграции, RAG, observability, RBAC, DR | архитектурное ревью |
| G8 | Реализация | код, IaC, тесты, контроль версий, контроль безопасности | quality gates |
| G9 | Пилот | пилотный акт, замеры, замечания, инструкции | принятие пилота |
| G10 | Промышленный контур | акты, мониторинг, сопровождение, улучшения | эксплуатационный допуск |

## Правила управления документами
Каждый документ: ID, версия, дата, автор/владелец, статус (draft/review/approved/obsolete), источники, допущения, связанные требования, история решений. Не выдавать гипотезы за факты. Не дописывать согласование заказчика без него. Изменения проходят change request и impact analysis.

## Роли RACI (проектные)
Спонсор: утверждает цели и бюджет; владелец процесса: утверждает BPMN/KPI; аналитик: BRD/SRS; юрист: квалификация нарушений, применение норм и допустимость доказательств; ИБ/ПД: модель угроз и политика доступа; архитектор: системные решения; разработчик: код; QA: тесты; оператор: эксплуатация. Пока это *проектные роли*, не реальные назначения.

## Иерархия продуктов
Главное ядро: OSINT_deepseek / FATHER OSINT; профиль: OSINT_TRICOLOR; знания: ALINA; граф: SecGraph; обучение: CyberED. Обратный перенос универсальных улучшений по upstream PR обязателен.
