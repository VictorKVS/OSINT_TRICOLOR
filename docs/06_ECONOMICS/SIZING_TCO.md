# E-001 Расчёты: sizing, TCO, ROI (модель, не фактический бюджет)
Обязательные входные параметры: N сигналов/сутки, средний размер исходного документа S MiB, доля повторов d, срок хранения R дней, пиковый коэффициент p, цена человеко-часа c, время обработки до/после t0/t1, стоимость инфраструктуры и API.

## Формулы
- уникальные сигналы/сут = N × (1-d).
- объём сырых документов за R суток GiB = N × S × R / 1024 (до резервных копий/индексов).
- пиковый intake за час = N / число активных часов × p.
- экономия часов/мес = N × 30 × (t0-t1) / 60 (если t в минутах).
- экономия ₽/мес = часы × c.
- TCO_36 = CAPEX + 36 × (OPEX infra + OPEX people + API + support + compliance).
- ROI_36 = (экономический эффект за 36 мес - TCO_36) / TCO_36.
Не считать сокращение затрат автоматически достижимым: необходимо замерить baseline, precision и загрузку.

## Сценарии для расчёта (ИСКЛЮЧИТЕЛЬНО гипотезы)
| Переменная | Малый пилот | Рабочая нагрузка | Масштаб |
|---|---:|---:|---:|
| N событий/сут | 100 | 2 000 | 20 000 |
| S MiB/событие | 0.5 | 1 | 2 |
| d | 0.2 | 0.35 | 0.5 |
| R дней | 30 | 180 | 365 |
| p | 2 | 4 | 8 |

Ориентир хранения только исходников: 1.46 GiB / 351.56 GiB / 14 257.81 GiB соответственно. Это НЕ оценка оборудования или бюджета; требуется отдельно считать БД, индексы, бэкапы, аудиожурнал/медиа, отказоустойчивость и компрессию.

## Порядок оценки
A) baseline по реальным данным → B) нагрузочное моделирование → C) CPU/RAM/GPU/disk/network → D) стоимость 3 альтернатив (local/on-prem/cloud) → E) анализ чувствительности API и LLM токенов → F) пилотное измерение → G) бюджетное решение.
