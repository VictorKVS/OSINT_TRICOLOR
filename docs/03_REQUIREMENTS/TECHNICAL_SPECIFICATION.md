# TZ-001 Техническое задание (системный уровень)
Версия 0.1; draft. Формат — рабочая спецификация, не заявлять о соответствии ГОСТ без формального нормоконтроля.

## Назначение
Профиль общего FATHER OSINT-агента для фиксации и анализа законно доступных публичных сведений о вероятных нарушениях прав медиакомпании.

## Функциональные требования
| ID | Требование | Критерий приемки |
|---|---|---|
| FR-001 | Реестр конфигураций источников и разрешений | неизвестный источник блокируется по умолчанию |
| FR-002 | Прием ручных и разрешённых автоматических сигналов | каждое событие получает ID и provenance |
| FR-003 | Канонизация URL и дедупликация | дубликаты связаны, оригинал не теряется |
| FR-004 | Каталог защищаемых объектов и лицензий | гипотеза может быть отклонена по известной лицензии |
| FR-005 | Версионные правила классификации | решение содержит версию правила и объяснение |
| FR-006 | Изоляция сырых данных и выводов модели | оригинал не перезаписывается выводом |
| FR-007 | Хранение хэшей, метаданных времени и цепочки доступа | изменения протоколируются |
| FR-008 | Граф связей с типизированными рёбрами и уверенностью | связи не тождественны установлению личности |
| FR-009 | Пакет кейса с цитированием источников | каждая фактическая ссылка проверяема |
| FR-010 | Очереди human review / legal review | внешние действия до одобрения недоступны |
| FR-011 | Управление жизненным циклом кейса | прозрачные статусы и причины решений |
| FR-012 | Экспорт Markdown/PDF после проверки | экспорт сохраняет версии и приложения |
| FR-013 | Журнал аудита и история доступа | можно восстановить последовательность действий |
| FR-014 | Реестр reusable improvements → OSINT_deepseek | для каждого CORE-кандидата есть статус upstream |

## Нефункциональные требования
NFR-001: RBAC и принцип минимальных полномочий. NFR-002: шифрование передачи и хранения чувствительных материалов. NFR-003: ПД минимизация, сроки хранения по утверждённой политике. NFR-004: idempotency, retry, bounded rate limits. NFR-005: trace IDs, метрики, логи без секретов. NFR-006: восстановление из резервных копий с проверкой. NFR-007: совместимость контракта общего OSINT ядра. NFR-008: разграничение mock/pilot/prod.

## Ограничения
Неиспользование скрытых систем/утечек, отсутствие обхода защиты, отсутствие правовой квалификации агентом как окончательного вывода, обработка только законных источников.

## Приёмка
Для каждого FR нужен автотест или протокол экспертного испытания и свидетельство в RTM. Приёмка невозможна без G4 (право/ИБ) и G6 (ресурсы).
